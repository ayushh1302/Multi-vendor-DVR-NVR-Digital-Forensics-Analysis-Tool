Core Forensic Capabilities

System Features & Modules

Every phase of the digital forensic lifecycle is engineered to satisfy law-enforcement standards, ISO criteria, and judicial evidentiary review. Click any module to expand details.

MODULE 01 Device Identification
+

Autonomous identification of physical DVR/NVR hardware, firmware builds, and partition structures directly from raw bitstream images or physical drive interfaces.

  • Automatically identifies DVR/NVR vendor, model, and firmware from raw disk images (.dd, .img, .E01, .raw) or attached media.
  • Signature-based matching against a built-in database covering Dahua, Hikvision, CP Plus, Honeywell, TP-Link, Godrej, Uniview, and Matrix.
  • Detects file system architecture (ext2/ext3/ext4, FAT32, HikFS, DHFS, and proprietary circular-tape layouts).
  • Extracts embedded serial numbers, MAC addresses, and channel counts directly from raw superblock structures.
MODULE 02 Forensic Acquisition
+

Hardware write-blocked bit-for-bit acquisition of connected surveillance drives with real-time cryptographic verification and damaged sector tolerance.

  • Bit-for-bit forensic imaging utilizing dd/dcfldd pipelines with write-blocking protection.
  • Concurrent MD5 and SHA-256 hashing during acquisition with byte-level verification of source vs. image.
  • Handles damaged or failing hard drives via specialized ddrescue-style recovery with retry logs and cluster maps.
  • Every acquisition phase and temperature threshold logged to an immutable chain-of-custody audit trail.
MODULE 03 File System Parsing & Proprietary Format Decoding
+

Parsing proprietary video containers and converting non-standard structures into standard ISO MP4 without re-encoding (lossless -c copy).

  • Parses standard and proprietary DVR file systems (ext2/3/4, FAT32, vendor-specific circular rings).
  • Extracts video files from proprietary containers: Dahua .dav, Hikvision .mp4/.hik, Honeywell .arf, and non-indexed binary streams.
  • Decodes proprietary headers and repackages video streams into standard MP4 for playback using ffmpeg without re-encoding (lossless -c copy).
  • De-interleaves and reassembles fragmented multi-channel video recorded across shared cylinder tracks.
MODULE 04 Deleted Footage Recovery
+

Low-level file carving from unallocated clusters, cylinder slack, and orphan allocation tables to reconstruct purged or overwritten recordings.

  • File carving from unallocated and slack space using vendor-specific header and packet signature matching.
  • Recovers deleted recordings even from proprietary circular file systems where commercial tools fail.
  • Aligns carved data boundaries strictly to H.264/H.265 keyframe (IDR) boundaries for maximum playback integrity.
  • Flags and stamps each carved artifact with empirical Recovery Confidence ratings.
MODULE 05 Timeline & Metadata Analysis
+

Multi-camera temporal synchronization that normalizes timezone offsets, daylight savings variations, and flags recording discontinuities.

  • Extracts per-file and per-frame metadata: recording start/end, camera channel, codec, resolution, and frame rate.
  • Normalizes all timestamps to UTC using the DVR's internal RTC timezone and DST rules.
  • Builds a synchronized cross-camera timeline that highlights recording gaps (evidence tampering or power loss).
  • Exports timelines to CSV, JSON, and self-contained interactive visual HTML reports.
MODULE 06 Integrity, Hashing & Chain of Custody
+

Cryptographic integrity verification ensuring mathematically verifiable provenance across every extracted file and recovered artifact.

  • Generates independent MD5 and SHA-256 hashes for the master disk image, every extracted video file, and every carved cluster.
  • Produces an automated Hash Manifest (CSV) covering the entire evidence repository.
  • Automated chain-of-custody logging: who, what, when for every action performed on the evidence.
  • All audit records and reports exportable for court submission under FRE 902(13)/(14).
MODULE 07 AI-Based Analytics
+

Air-gapped machine intelligence scanning high-volume video archives to index persons, vehicles, faces, and anomalous motion events.

  • Face detection and object classification (person, vehicle, animal) using air-gapped pre-trained YOLO models.
  • Motion detection via adaptive background subtraction and temporal frame differencing with tunable thresholds.
  • Scans multi-channel footage, flagging significant events with microsecond timestamps and confidence scores.
  • Outputs annotated keyframe JPEGs and structured detections CSV so analysts jump directly to critical moments.

Getting Started

BRUCH.DFA is deployed as an enterprise command-line suite and headless processing backend. It integrates with standard Linux forensic distributions (CAINE, SANS SIFT, Kali Linux) and standalone server environments.

BASH — REPOSITORY CLONE & INSTALL 
git clone https://github.com/ayushh1302/Multi-vendor-DVR-NVR-Digital-Forensics-Analysis-Tool.git
cd Multi-vendor-DVR-NVR-Digital-Forensics-Analysis-Tool
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

System Requirements & Dependencies

  • Host Operating System: Linux (Ubuntu 22.04 LTS+, Debian 12, RHEL 9, CAINE 13.0).
  • Core Runtime: Python 3.10 or higher.
  • System Binaries: ffmpeg (v5.1+ compiled with libx264/libx265), dcfldd, ddrescue, libewf.
  • Hardware Write-Blocker: Tableau T8u, WiebeTech UltraDock, or kernel-level read-only write-blocker (blockdev --setro).
SOP-01

Standard Operating Procedure: Drive Acquisition

Acquisition must guarantee bitstream preservation of the target storage medium. Physical DVR drives must never be mounted directly by operating systems to prevent automatic journal replay or partition modification.

BASH — BIT-FOR-BIT ACQUISITION WITH DUAL HASH 
# Verify drive is write-protected
sudo blockdev --getro /dev/sdb

# Execute bitstream acquisition with concurrent MD5 & SHA256 hashing
dcfldd if=/dev/sdb of=/evidence/case_01/raw_disk.dd \
  hash=sha256,md5 \
  sha256log=/evidence/case_01/sha256.log \
  md5log=/evidence/case_01/md5.log \
  status=on bs=64k

Standard Operating Procedure: Device Identification

SOP-03

Standard Operating Procedure: File System Parsing & Lossless Repackaging

Proprietary video containers (.dav, .arf, .hik) contain standard H.264/H.265 elementary streams wrapped in non-standard transport packets. BRUCH.DFA strips the proprietary wrapper and demuxes to standard MP4 without re-encoding, ensuring bit-accurate preservation.

CLI — EXTRACT & LOSSLESS REPACKAGE 
python3 -m bruch_dfa extract \
  --image /evidence/case_01/raw_disk.dd \
  --dest /evidence/case_01/extracted_videos/ \
  --repackage mp4 \
  --threads 8
SOP-04

Standard Operating Procedure: Unallocated File Carving

When video tracks are deleted or sectors are orphaned due to circular overwrite, the carver sweeps unallocated space, identifies OEM video headers, and rebuilds valid video files starting and ending at keyframe (IDR) boundaries.

CLI — DEEP UNALLOCATED CLUSTER CARVE 
python3 -m bruch_dfa carve \
  --image /evidence/case_01/raw_disk.dd \
  --vendor dahua \
  --dest /evidence/case_01/carved_footage/ \
  --min-size 1MB \
  --keyframe-align

Evidentiary Compliance

Forensic Evidentiary Privacy Policy

Effective Date: September 2026 | Compliant with CJIS Security Policy & ISO/IEC 27037:2012

1. Absolute Zero-Telemetry Guarantee

BRUCH.DFA operates entirely locally on the examiner's workstation or air-gapped forensic server. At no point are seized disk images (.dd, .img, .E01), carved video clips, extracted timestamps, or evidentiary metadata transmitted over external networks or stored in public clouds.

2. Criminal Justice Information Services (CJIS) Adherence

All evidence processing adheres strictly to FBI CJIS Security Policy requirements for handling Criminal Justice Information (CJI). Forensic logs, audit records, and user session identifiers are protected using FIPS 140-3 validated cryptographic standards.

3. Physical Storage & Inode Data Handling

Physical hard drives attached to the BRUCH.DFA system are mounted solely in write-blocked read-only mode (blockdev --setro). The software does not modify source master drives, disk superblocks, or cylinder allocation maps.

4. Cryptographic Hashing & Proof of Non-Tampering

Dual MD5 (RFC 1321) and SHA-256 (FIPS 180-4) hashes are generated concurrently upon ingestion. Cryptographic manifests are stored in immutable local audit logs to prove that no alteration occurred between original seizure and court presentation.

5. Local Session Tokens & Cookie Usage

The platform utilizes essential browser session storage strictly for maintaining examiner authentication tokens and local user preferences. No advertising cookies, third-party analytics scripts, or behavioral tracking mechanisms are deployed.
